# 任务一：全连接神经网络（MLP）推理加速器
## 8人团队详细分工计划书

从无 Bias 的轻量 MLP 起步：$28\times28$ 图像展平为 784 维，经过 64 个隐藏神经元和 ReLU，再输出 10 个分类分数，最后用 Argmax 给出数字类别。即：

$$\text{28}\times\text{28} \longrightarrow \text{展平 784} \longrightarrow \text{FC1}(784 \to 64) \longrightarrow \text{ReLU} \longrightarrow \text{FC2}(64 \to 10) \longrightarrow \text{Argmax}$$

784-64-10 是初始建议，需由 Python 准确率与综合资源共同决定。若准确率不足，B 先检查训练、归一化和输入顺序，再比较隐藏层 32/64/128 等规模；扩大模型后必须重新评估存储和计算开销。

硬件由输入缓存、权重存储、共享 MAC 核心、中间结果缓存、控制与地址生成、Argmax 组成。FC1 和 FC2 顺序执行，通过层参数和地址切换共用 MAC 资源。D 与 E 必须从综合层次、算子实例或调度结果证明实际发生复用，不能只凭软件中调用了同名函数判断。

自采数据链路建议为：

$$\text{原始照片} \longrightarrow \text{图像解码} \longrightarrow \text{灰度转换 / 极性统一} \longrightarrow \text{前景/背景判断} \longrightarrow \text{ROI裁剪 / 等比例缩放} \longrightarrow \text{补边居中为28}\times\text{28 / 统一归一化} \longrightarrow \text{MLP}$$

JPEG/PNG 解码放在主机或 Testbench；G 负责将有明确输入尺寸上限的像素预处理映射为 HLS 模块。图像格式、输入尺寸上限、软件和 HLS 的分界必须写入设计说明。Level 2 端到端验证复用已通过 Level 1 的网络与权重。

### B: MNIST 数据与 Python 浮点模型负责人
* 自行下载 MNIST，提供自动下载入口、原始文件校验和、数据来源及缓存位置；训练集与测试集分别下载。
  * *注*：MNIST 官方数据包括 60,000 个训练样本和 10,000 个测试样本。建议从训练集划分 55,000 训练 / 5,000 验证，固定随机种子；最终测试集不参与训练、缩放校准或超参数选择。参考 [MNIST 原始说明](http://yann.lecun.com/exdb/mnist/)。
* 建立无 Bias 的 MLP 浮点模型，保存权重、模型定义、训练配置、随机种子和依赖版本。
* 固定输入极性、像素归一化和展平顺序；导出权重、测试图像、标签、逐层输出和分类结果。
* 与 C 共同检查参数导出无转置、缺项或顺序差错，为 F 提供可追溯标准答案。
* **交付物**：下载脚本、数据说明、模型与权重、推理入口、权重导出程序、参考结果。
* **验收标准**：下载后核对训练/测试数量、图像尺寸和标签范围；验证集准确率建议达到 95% 以上再冻结模型，最终测试集另行报告（95% 为组内留出量化余量的建议值，不是课程规定）。
  * *注*：下载入口可使用 Torchvision 的 `MNIST(..., train=True/False, download=True)`。下载脚本同时覆盖两种划分，并提供网络失败后校验本地原始文件的路径。参考 [Torchvision MNIST 文档](https://pytorch.org/vision/stable/generated/torchvision.datasets.MNIST.html)。

### C: 定点量化与数值分析负责人
* 在训练/校准数据上统计每层权重、激活和累加值范围，记录异常值和所留裕量。
* 明确权重、输入、隐藏激活、输出、乘积及累加器各自的总位宽、整数位和小数位，统一舍入与溢出策略。
* 可从 16 位权重/激活作为候选高精度起点，先确认可用，再比较更低位宽。累加器独立选择更宽格式，不能默认与权重同宽。
* 编写匹配 HLS 行为的定点参考实现，包括缩放、截断/舍入、饱和/回绕以及每个类型转换的位置。
* 保留逐层缩放公式与参数，验证层间尺度衔接。不能把所有数据任意归一化后直接送入原模型。
* 基础阶段至少完成“可用配置”和“更高位宽配置”的准确率及资源对比；加分阶段再扩展扫描。
* **交付物**：定点格式表、范围统计、量化脚本、定点权重、位精确参考结果、精度损失分析。
* **验收标准**：最终硬件仿真准确率 $\ge 90\%$；建议定点相对浮点下降不超过 1 个百分点（该差值为组内目标）。与 D/F 逐层验证一致；若有差异，必须定位到具体算术规则。
  * *注*：实现时注意 `ap_fixed<W,I>` 的 $W$ 包含符号位，小数位为 $W-I$；不同数据类别的格式应分别记录。参考 [AMD 定点类型说明](https://docs.xilinx.com/r/en-US/ug1399-vitis-hls/C-Arbitrary-Precision-Fixed-Point-Types)。

### D: HLS 运算数据通路负责人
* 实现可复用点积/MAC 核心，以受控循环完成全连接运算，避免全层完全展开导致资源膨胀。
* 实现 ReLU 与 Argmax，约定并列最大分数时的输出规则。
* 支持 FC1 和 FC2 的不同输入输出长度，并配合 E 切换权重和缓存地址。
* 按 C 的定义实现乘法精度、累加器、缩放和输出转换，提供调试模式下的中间结果导出。
* 与 H 评估流水线和小规模并行配置，保留一套低并行度稳定实现。
* **交付物**：MAC/FC/ReLU/Argmax 源码、算子级测试、数据通路图、优化前后记录。
* **验收标准**：覆盖正负乘积、全零输入、最大幅值、累加边界、ReLU 负输入及 Argmax 并列等案例；与位精确参考一致，并通过 HLS 综合。

### E: HLS 存储与控制负责人
* 定义权重存储布局、输入缓存、中间激活缓存、结果缓存和层描述参数。
* 实现权重与特征的地址生成，检查数组边界、偏移、层间写回和新样本清理。
* 设计加载、FC1、激活、FC2、分类、结束等控制阶段；采用 HLS 控制代码并说明对应状态，不额外要求手写 RTL 控制器。
* 配合 D 保证两个 FC 层复用同一计算资源，配合 H 确认存储端口数与并行度匹配。
* 使用小规模人工参数及递增编号权重验证地址映射，再接入真实模型。
* **交付物**：存储/控制源码、地址映射表、控制状态表、层间时序示意。
* **验收标准**：连续多样本无状态残留，地址不越界，层切换正确，综合结构能够说明资源复用与存储映射。

### F: 仿真验证与故障定位负责人
* 编写统一 Testbench，读取样本、标签与参考结果，自动统计准确率、逐层偏差和错误样本。
* 先做 10 张人工可检查样本，再做约 100 张各类数字覆盖测试，最终完成标准测试集全量验证。
* 分别记录 Python 浮点、Python 定点、HLS 浮点 C 仿真、HLS 定点 C 仿真和 RTL 仿真的结果，标明仿真层级、样本数量与运行配置。
* 保存浮点 HLS 对照分支；按照任务书“浮点数/定点数”的表述，安排浮点与定点硬件仿真对照。最终可综合交付以满足要求的定点版本为主。
* 定点 RTL/C-RTL 联合仿真按完整 10,000 张测试集安排，支持分批、日志落盘和中断续跑。浮点对照也应尽早估计 RTL 仿真工期并排入机时。
* 遇到差异时按输入 $	o$ FC1 $	o$ ReLU $	o$ FC2 $	o$ Argmax 定位，不只比较最后类别。
* 负责 Level 2 端到端回归和现场演示脚本。
* **交付物**：Testbench、运行脚本、准确率 CSV、逐层差异记录、错误样本清单、仿真日志、演示入口。
* **验收标准**：正式结果的样本清单可追溯、无缺失或重复；基础定点准确率 $\ge 90\%$；标准答案、模型和权重版本一致。
  * *口径约束*：C 仿真检查 C/C++ 模型；C/RTL 联合仿真检查生成 RTL 与 C 模型的一致性。报告须区分两者，不能把 C 仿真准确率或小样本 RTL 通过率直接写成全量 RTL 准确率。参考 [AMD Vitis HLS 说明](https://docs.xilinx.com/r/en-US/ug1399-vitis-hls)。
  * *注*：任务书未细化 C 仿真与 RTL 覆盖数量的边界，因此本计划采用较充分的全量 RTL 排期。若实际机时成为阻碍，A 应带着已完成的覆盖率、耗时和替代验证方案向教师确认验收口径，不能自行降低标准。

### G: 自采数据与预处理负责人
* 制定统一采集规范：一张图一个数字，保留原始照片、标签、书写者、采集批次和光照信息。
* 建议每人提供 0-9 每类 10 张，共 100 张，8 人共 800 张；每人另提供 10 张空白、桌面或杂乱背景，共 80 张（上述数量为组内建议）。
* 将数字图像按书写者或采集批次划分为调试集和最终评测集，避免同一原图及其变换版本跨集合。可采用 2 位书写者调试、6 位书写者评测；明确两集合数量。
* 建立 Python 预处理参考：灰度、极性统一、前景判断、ROI 裁剪、等比例缩放、补边居中、归一化。
* 实现输入尺寸有界的 HLS 像素预处理模块。先完成简洁的裁剪/缩放/居中流程，再根据误差分析增加必要处理。
* 与 B 保证预处理结果和 MNIST 输入约定一致；与 F 完成预处理逐像素比对和端到端验证。
* 在相同自采评测样本上比较“仅做必要格式转换”与“完整预处理”，分析收益和剩余错误；比较 MNIST 与自采集的准确率差异。
* 背景样本单独统计。若增加前景阈值或拒识逻辑，报告背景误接收率以及有效数字误拒率；不得把背景硬塞为 0-9 之一计入数字准确率。
* **交付物**：采集规范、原始与处理后数据、标签清单、划分清单、预处理源码、处理前后示例、混淆矩阵、错误分析。
* **验收标准**：输出 $28\times28$ 单通道，标签可追溯，预处理与网络端到端贯通；自采结果如实报告，任务书未规定其最低准确率。

## 三、接口冻结与协作规范

最迟 9 月 4 日形成第一版接口契约；9 月 5 日补齐实测范围支持的定点参数。先以统一候选类型开发，参数修改由 C 同步给 D/E/F。以下项目不得口头约定：

| 接口项目 | 统一约定 |
| :--- | :--- |
| **图像** | $28\times28$、单通道；像素极性、范围、归一化、行优先展平 |
| **网络** | 层尺寸、ReLU 位置、无 Bias、分类输出规则 |
| **权重** | 建议 `W[out][in]`；导出顺序、层偏移、文件格式、校验和 |
| **定点** | 各数据类型 W/I/F、缩放、累加精度、舍入、溢出规则 |
| **运算/存储** | 缓存读写权限、索引范围、运算完成与层切换条件 |
| **输出/调试** | 类别 0-9；可选 10 维分数；中间值只在调试模式导出 |
| **工程** | 完整器件型号、时钟、工具版本、运行入口、报告位置 |
| **数据版本** | 图像与标签一一对应；固定训练/校准/验证/测试划分 |

> **规则**：权重、位宽、预处理或网络结构变更时，由发起人更新配置说明，通知依赖成员，并触发相应回归。最终实验用冻结版本，不允许不同图表混用不同权重或样本集合。
