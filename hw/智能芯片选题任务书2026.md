## 一、总则

### 1.1 选题结构
本次大作业设两条并行的基础技术路线，各团队须任选其一：
* **路线 A**：以全连接神经网络（MLP）为加速对象；
* **路线 B**：以卷积神经网络（LeNet-5 结构）为加速对象。

两类路线在验证深度上均涵盖 Level 1 与 Level 2 两个层级，并共享高级进阶任务（Level 3），作为 10 分奖励分（最终成绩）。

| 层级 | 名称 | 核心要求 |
| :--- | :--- | :--- |
| **Level 1** | MNIST 标准数据集验证 | 基于标准测试集完成功能仿真与综合，结果 $\ge 90\%$ |
| **Level 2** | 自采数据验证 | 自行采集手写数字图像，设计预处理数据通路，报告准确率变化并完成精度损失的原因分析 |
| **Level 3** | 量化与资源权衡 | 定点量化，位宽选择与资源开销对比 |

> **层级关系**：Level 2 须建立在 Level 1 已通过验证的实现之上；Level 3 须建立在 Level 1 或 Level 2 的可运行版本之上。

### 1.3 知识基础与技术要点

#### 1.3.1 基础知识
* **数字逻辑与计算机组成**：状态机、存储器、数据通路的基本概念。
* **神经网络前向计算**：卷积、池化、全连接、ReLU 是怎么算的；本课程只做推理，不涉及训练算法本身。
* **实现手段**：HLS (C/C++)

#### 1.3.2 技术要点
* **面向硬件约束的网络轻量化设计**  
  算法设计须主动适配底层硬件开销。例如，非线性激活选用符号位判别的 ReLU，下采样选用基于比较逻辑的最大池化；精简全连接层规模并移除偏置项（Bias），以削减片上存储与累加资源占用。其核心目标在于最大限度压缩参数规模与计算复杂度，降低硬件实现门槛。
* **定点量化与位宽寻优策略**  
  针对定点硬件架构实施量化转换，流程分为两阶段：首先对模型参数进行动态范围归一化（如按最大绝对值缩放至 $[-1, 1]$ 区间）；随后在 Python 仿真环境中开展位宽敏感度分析，在保证任务准确率的前提下确定最小可用位宽（如对比 8 位至 16 位量化精度，选取性能饱和的 11 位临界点），以优化片上资源占用。
* **计算单元的时分复用机制**  
  避免采用逐层直连的“全展开”硬件架构，转而实施计算资源的时分复用。通过设计统一的高复用度计算核心（如单套 $3\times3$ 卷积阵列），配合控制状态机与数据流调度，使多层卷积乃至全连接运算共用同一算子模块。
* **硬件资源约束与并行度权衡分析**  
  计算吞吐率的提升受限于物理器件的资源容量。团队须在不同位宽与并行度配置下开展设计空间探索（DSE），评估吞吐率（如 625 FPS）与资源利用率的平衡关系，重点分析因高位宽或大并行度引发的资源溢出边界，建立对性能-面积（PPA）权衡的系统认知。
* **基于分层比对的仿真验证方法**  
  构建以软件模型为基准的 Testbench 验证流程。将测试样本注入硬件仿真环境，统计推理准确率并与算法模型对齐；当出现功能偏差时，采用逐层导出硬件中间特征图并与软件结果位对齐的比对方法，实现故障模块的精准定位与调试。
* **面向真实场景的预处理流水线与鲁棒性验证（Level 2）**  
  针对真实采集图像与标准基准数据集（如 MNIST $28\times28$ 单通道灰度图）在分辨率、色彩通道、畸变与光照噪声层面的域差异（Domain Gap），构建端到端预处理流水线（包含灰度转换、反色处理、ROI 裁剪与尺寸缩放等）。同时引入无目标背景样本开展抗干扰测试，提升系统在实际部署环境下的判别鲁棒性。

## 任务 1：全连接神经网络（MLP）推理加速器的硬件实现与仿真验证（路线 A）

### 1. 任务目的
本任务旨在引导团队经历从高层算法模型到可综合硬件描述的完整设计流程，建立“算法—体系结构—数值表示”协同约束的系统观。其核心目标与设计思想主要体现在以下三个维度：
1. **结构维度**：明确神经网络推理的硬件本质在于规则化的乘累加（MAC）运算。硬件加速器的设计核心是运算单元、片上存储层次与控制时序三者的协同优化，而非算法代码的机械转译。各团队在设计中需理解数据通路（Datapath）与控制器（Controller）的设计与实现方法。
2. **数值维度**：确立定点表示作为硬件实现的首要刚性约束。鉴于浮点运算在 FPGA/ASIC 上的高昂开销，团队须深刻理解模型参数与激活值向有限位宽的定点化映射，明确该步骤为硬件落地的必要前置条件，而非可选项。
3. **验证方法维度**：本次实验以仿真为唯一验证手段。团队须报告硬件仿真在测试集上的识别准确率（浮点数/定点数）。

### 2. 考核指标

| 考核维度 | 评价准则 |
| :--- | :--- |
| **Level 1 功能实现** | 硬件仿真在 MNIST 测试集上跑出识别准确率，与自建 Python 模型的准确率对照，差值处于合理范围；工程在 XC7Z020 上综合通过并导出完整资源报告。 |
| **定点实现** | 数值格式（符号位/整数位/小数位）的选择有实验依据；能说明所选位宽相对更高位宽在资源上的节省。 |
| **体系结构设计** | 存储组织与地址生成方案清晰；运算模块与控制调度模块的职责划分明确；具备模块框图与数据流说明；体现至少一处硬件复用（如全连接层复用卷积/乘累加单元）。 |
| **Level 2 数据采集与预处理** | 预处理链路完整；输出格式与 MNIST 一致（$28\times28$ 单通道）。 |
| **Level 2 结果分析** | 给出 MNIST 测试集与自采数据集的准确率对照；对准确率变化作出解释。 |
| **答辩与演示** | 现场运行仿真并展示识别结果；就听众的问题准确解答；全体成员对整体方案均有基本掌握，而非仅本人负责的模块。 |
| **提交物** | 源代码、中期报告、期末报告。 |

## 任务 2：卷积神经网络（LeNet）推理加速器的硬件实现与仿真验证（路线 B）

### 1. 任务目的
本任务以具备数据复用特性的卷积算子为实现对象，使团队理解“循环变换即体系结构变换”这一高层次综合的基本命题：同一段算法描述在施加不同的循环展开、流水化与存储分割约束后，将映射为吞吐率、资源占用与访存需求截然不同的硬件结构。

据此，团队须在指定器件的资源预算下，通过受控实验完成并行度的定量选择，建立“性能并非可任意设定的目标，而是资源约束下的可达点”这一工程判断力，进而形成对算力、带宽与面积三者权衡关系的实践认识。

此外，本任务通过分模块实现与逐级验证的组织方式，训练团队对复杂设计进行层次化分解与故障定位的能力，对应课程预期学习成果中关于数据通路与控制器设计方法、以及故障分析与定位方法的要求。

## 任务 3：面向精度——资源权衡的定点量化与设计空间探索（Advanced Requirements / Extra Bonus，10分）

### 1. 进阶目的与适用路线
本任务不构成独立选题，而是任务 1 与任务 2 的共同技术延伸方向，适用于两条路线中的任意一条。其与基础任务的衔接关系体现于三个层面：
1. **基线复用**：本任务直接复用团队在基础任务中已通过验证的网络实现作为基线，不重复考核实现工作量。基础任务中所采用的数值格式在此成为设计空间中的一个采样点，而非终点。
2. **系统性设计空间探索**：基础任务对定点格式的处理属于“确定一组可用参数”的验证性工作；本任务则要求转为以刻画权衡关系为目标的系统性设计空间探索，须识别精度—资源曲线的边际收益拐点乃至帕累托前沿，并结合应用场景约束给出推荐工作点。
3. **权衡观念确立**：本任务旨在使团队确立“数值精度是可与面积、延迟、吞吐率相互交换的设计变量”这一芯片设计核心权衡观念。需特别指出，本次实验虽不进行上板测试，量化工作的价值并不因此削弱——量化的收益本就体现于综合报告的资源与时序数据之中，而非依赖实测。

### 2. 涉及的具体进阶知识点

#### (1) 量化理论与方法
* **训练后量化（PTQ）与量化感知训练（QAT）的机理差异**：掌握两者的原理、精度边界与适用场景；明确本任务限定于 PTQ 范畴，无需进行重训练。
* **全局缩放的理论依据与量化映射**：基于卷积层与全连接层的线性乘加特性（权重等比缩放导致输出同比例缩放）以及 Softmax 的单调保序性，明确等比缩放不改变最终分类决策；据此通过单轮前向传播统计数值的最大绝对值，并引入裕量系数计算缩放因子，将全部权重与中间激活值映射至 $[-1, 1]$ 区间。
* **位宽敏感度扫描方法**：在 8–16 bit 位宽区间内，逐位评估定点模型与浮点模型的推理误差，以“在维持分类准确率的前提下最小化硬件位宽”为寻优判据。
* **差异化定点位分配策略**：针对权重与激活值采用异构的定点格式划分（整数位与小数位分配）；对于非负特征数据，可省略符号位以提升 1 位小数精度。
* **逐层量化敏感度与混合精度分析**：分析各网络层对量化噪声容忍度的差异，探索其与层内动态范围及参数规模的关联性。
* **极低比特量化的精度退化与硬件收益**：分析 INT4 条件下的表征能力退化与误差累积机理；探究二值化神经网络（BNN）中乘累加运算退化为同或（XNOR）与位计数（popcount）操作所带来的硬件开销收益及伴随的精度代价。

#### (2) 设计空间探索与评估方法
* **设计空间维度界定与采样策略**：明确单变量扫描与双变量交叉采样的适用场景，严格遵循控制变量原则展开参数探索。
* **帕累托前沿（Pareto Frontier）与非支配解识别**：掌握多目标优化中的帕累托前沿概念，建立非支配解集的筛选与判定方法。
* **归一化评估指标构建**：构建多维综合评价指标，涵盖单位资源吞吐率、单位面积算力密度及峰值可达帧率。
* **边际收益拐点的量化判据**：建立性能提升与资源开销边际效益拐点的数学量化与判定准则。
* **应用场景约束与设计指标映射**：掌握不同部署场景的权衡准则——边缘侧受限于资源与功耗，实时系统受制于端到端延迟，云端侧则以吞吐率为核心导向。

### 3. 考核标准（满分 10 分）

| 评分项 | 分值 | 达成标准 |
| :--- | :---: | :--- |
| **位宽扫描实验** | 3 分 | 在基础版本之外，另做不少于三档位宽（如 8/6/4 bit）；每一档都给出三个实测数字：准确率、资源占用、延迟。数字必须来自仿真和综合报告，不许估算。 |

| **工程结论** | 2 分 | 用一段话回答：如果这个设计要真用起来，你推荐哪个配置、为什么；结论须有前面的数据支撑。 |
